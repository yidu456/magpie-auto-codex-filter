# Findings

- Legacy makeProxy captures mode in its closure; mode also determines service identity and recovery ownership.
- Exact Azure, encrypted-content, throttle, ALB, transport, incomplete-stream and availability handlers can be gated without broadening matching.
- Browser requests are rejected by the proxy; management must be a separate loopback server.
- Current stop forces connections closed after 10s; console will instead refuse exit while active.
- Node 24.12 SEA and current node.exe available. Runtime binary is 89935872 bytes, not a memory measurement.
- Default CLI runtime stays untouched; console runtime and tests are isolated.
- Portable config supersedes per-launch OFF: startup follows enabled; exit preserves it.
- Pending web-token changes require an active-token runtime cache for duplicate launch.
- Recovery errors must publish the control server; failed activation without a journal can be corrected directly.
- Explorer exit status was unreliable; Windows ShellExecute dispatch and local browser requests were verified.
- User launched dist/portable/MagpieFilter.exe during handoff; preserve its generated configuration and runtime.
- Comparison baseline: upstream main 837f793 publishes V11 on 2026-10-27; standalone dev 2649f98. Both tracked worktrees initially clean.
- V11 documentation advertises lazy history, first-delta streaming, expanded retry classes, and a persistent daily metrics dashboard. Standalone already has conditional history and selectable unbuffered streaming; exact semantics need source comparison.
- Source confirms V11 buffers pre-delta SSE to retain early-error retries, then streams without replay. Standalone bufferResponse=false pipes successful SSE immediately without inspecting early in-band errors; true buffers the entire round.
- V11 lazy history always forces store=false and rejects references/compaction before forwarding; standalone conditional mode preserves store and delegates references/compaction to Magpie unless cleanup becomes necessary. Standalone also handles invalid_encrypted_content, absent from V11 lazy downgrade matching.
- V11 adds explicit relay/server error classes and a generic HTTP >=500 fallback (broader in code than README's JSON wording). Standalone HTTP branch currently also lacks detected===transport acceptance for V10 HTTP-wrapped disconnections; verify this difference with isolated mocks before reporting.
- V11 Recorder provides latency/token/error/retry series and same-day persisted aggregates; standalone UI has controls and bounded event rows but no equivalent Recorder. V11 async batch log writer is absent from standalone console logging, which uses appendFileSync.
- Fresh isolated comparison assertions confirmed: generic JSON 502 and HTTP 400 wrapped stream_disconnected retry only in V11; invalid_encrypted_content cleanup retries only in standalone conditional mode; early SSE Azure retries in V11 and standalone buffered mode but not standalone unbuffered mode; early SSE bad_response retries only in V11. Successful unchanged request whitespace preserved only by V11 with core filtering enabled.
- Recommendation: selectively adapt bounded relay retries, pre-delta protected streaming, metrics, raw JSON preservation, and async logging. Do not replace Magpie routing, conditional compaction/reference delegation, existing encrypted-content cleanup, policy snapshots, or portable console lifecycle with CCS-specific V11 defaults.

Current actions/runner-images table lists macos-15 as arm64 and macos-15-intel as x64; Windows2022 and Ubuntu22.04 x64 are available. gh release create --verify-tag prevents implicit tag creation; upload/publish is multi-request so draft-first failure containment is needed.
